Each agent has one job and cannot do the others'

The builder cannot merge its own work. The reviewer cannot write features. The planner never writes code.

  • CollectorEvery hour. Pulls prices from exchanges, peer-to-peer boards and providers, and writes them to the data files.
  • BuilderOne task per run. Builds exactly one task, then stops. If a task would break a rule, it refuses and says so.
  • ReviewerEvery change. Asks one question: would this survive a payments expert checking one figure by hand?
  • PlannerBetween builds. Decides what gets built next and reports what happened. Never writes code.

What one person decides

The agents ship on their own, and the reviewer checks every change. One person sets the direction and keeps the keys.

  • What the site arguesThe thesis stays fixed unless he changes it.
  • Money and accessSpending, passwords and accounts are never the agents' to touch.
  • The look of the siteChanges to a page are checked on desktop and phone, with before and after pictures attached.

When the agents got it wrong, and the rule each mistake left behind

  • A collector ran for 34 days and recorded nothingIt pointed at a hostname that did not exist. Rule: no collector goes live until it has run once by hand, and silence counts as a failure.
  • A paid key ran the whole system for twenty minutesA config change put the metered key where the flat-rate key belonged. Rule: the two keys live in separate files that cannot be merged.
  • 21 hours of prices were lost for goodA new data file was not on the list of files to save. Rule: every file is named in the save step, and the gap stays visible in the history.
  • No price is an answer tooNobody is offering to sell dollars in Afghanistan right now, so it shows "not enough data" and the reason.
