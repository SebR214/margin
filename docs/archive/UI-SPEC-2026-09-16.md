## U6 — One chart component, Revolut style

Every chart on the site comes from one component. Anatomy, in order:

1. Headline: the current value, large (34px, weight 800), tabular numerals.
2. Under it: the change over the window shown, e.g. "+3.9 points ▲ 4.6%". Up is indigo, down is #D0453B.
3. Plot: 1.6px indigo #5A55E0 line, area fill gradient from #DCDFFA at 0.95 opacity down to 0.05 at the baseline. No gridlines, no axis lines.
4. Right gutter: up to three value labels, evenly spaced, 11px #9A9A9A. Skip any label that would collide with the badge.
5. Current value: a 1px dotted indigo line across the plot at the latest value, and an indigo badge with white bold text at the right edge.
6. Bottom: up to four date labels, 12px #9A9A9A, first left-aligned, last right-aligned.
7. Optional range pills, centered under the plot: 1h 6h 1d 1w 1m 3m 1y All. Selected is a white pill on a #F6F6F6 track. Pills only where more than one window actually exists in the data — never show a range the data cannot fill.

Gaps in the series render as gaps in the line. Never interpolate across a missed pass; delivery has already been 20/24 in a week, so this will happen in week one.

Hover shows the point's value and its timestamp. `prefers-reduced-motion` and no-JS get the chart fully rendered, static.

Replace every existing sparkline and line chart with this component.

**How it works** — rewrite as plain prose with one bulleted list. No two-column label/text grid, no section-title column. Content, in order:

## R1 — The receipt behind every number

For each published index number (currency + hour), expose a receipt:

* The evidence: how many offers, the median, the source kind, the collection timestamp.
* The official rate used: value, timestamp, source file.
* The computation: numerator, denominator, result.
* The evidence-rule check: required vs actual, and the verdict.
* The file paths behind each of the above.

Build it from what is already stored (`p2p_basis.csv`, `fx_rates.csv`, `index_latest.json`). Where per-offer rows were never stored, the receipt uses the stored aggregates. Do NOT reconstruct individual offers that were not saved.

Separately, and starting with the next collection pass: persist the individual offer rows so future receipts can show them. History cannot be backfilled, so this starts now, not later.

## R2 — The receipt replay

Every published number on the site becomes clickable. Clicking opens a centered overlay, per the "The receipt replay" board, that replays four steps over about three seconds:

1. The evidence — the offers collected and the median, with the timestamp.
2. The official rate — captured in the same pass.
3. The math — the division, ending on the published figure.
4. The verdict — published because the evidence rule was met, with required vs actual.

Each step names its file on the right. Footer links to the raw files. ESC and click-outside close it. `prefers-reduced-motion` and no-JS render the whole receipt at once, no animation.

The overlay must never compute or round differently from the number that opened it. It reads R1's output; it does not recalculate.

## M2 — The machine room page

New page and nav item, per the board. One plain-language intro, then three columns:

* **This hour's collection** — the pass ticking through sources, each line showing the currency, the source kind, and the verdict (priced with its evidence count, or withheld with its reason). Withheld lines in #B3822D.
* **What the agents are doing** — issues filed, reviews, PRs, commits, in one feed with the agent's name. A stopped or broken loop is shown as stopped, in plain words. This is the point of the page: unedited means unedited.
* **Where things stand** — six meters: priced this hour, withheld with reasons, collector commits today, open pull requests, unbroken hours of history, people working here (1).

When nothing is happening, say so ("collector idle, next pass on the hour"). Never fabricate activity to fill the page.

Home gets one line above the ask box linking here: the machine-room label, a live one-line status, and "watch it run →". One line, no widget.
