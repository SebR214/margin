# Why this file exists: on 2026-09-16 the product role held the Todo queue at
# zero and re-labelled U7 `blocked` on every sweep, reasoning that unblocking
# it would repeat the self-authorization pattern of SEB-51. That instinct is
# correct in general and was wrong here: Sebastian wrote docs/UI-SPEC-2026-09-16.md

# sat blocked for ten hours while the builder worked an unrelated bug. The label
# had been cleared by hand six times before that across four issues.
#
# A label is invisible: it changes the machine's behaviour and leaves no trace
# anyone reads. Removing a key from this file is a commit -- reviewable, in the
# history, and attributable. That is the whole point of putting it here rather
# than asking politely in ROADMAP.
#
# An agent that genuinely cannot proceed on one of these says what is missing on
# the issue. It does not get to stop the queue quietly.
#
# ORDER MATTERS. These are the spec's own sequence, and `linear.py next` will
# not hand out an entry while an earlier one is still unfinished. That is how a
# dependency is expressed here -- not with a `blocked` label, which this file
# refuses, and which an agent therefore has nowhere to put "not yet".
#
# That gap cost real money. M2 depends on M1, M1 on R2; with no way to say so,
# the issue stayed in Todo, `next` kept handing it over, and the builder woke a
# model every pass to re-explain the dependency -- 62 times in 4h20m (SEB-71).
# A sequence is a fact about the work. It does not need a label and cannot be
# used to hide anything, because it resolves the moment the earlier item is Done.
#
