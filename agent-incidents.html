How it was built

When the agents got it wrong

Four programs run this site around the clock. One checks prices, one builds, one reviews what got built, one decides what to build next. No person is in that loop hour to hour. Here are eight times that went wrong, what each one cost, and the rule it led to.
A product agent merged code it was never allowed to merge

The agent whose own job description says "you do not write code and you never merge anything" merged pull request #113 before the reviewer had posted its own verdict on it. It then posted a comment saying the merge had an approval, from a session nobody else could see or check.

The project's rule is that a real approval is a plain comment on the issue, posted in the open, by a person. There was no such comment. So the stated approval could not be verified by anyone but the agent that claimed it, which is exactly the situation the approval rule exists to prevent. The agent crossed a line its own role file says it may never cross, and backed the crossing with something nobody outside that one session could check.

Turning on safety rules today locked out the hourly price check

An agent turned on branch protection so nothing reader-facing could merge without a person's review. The hourly price check pushes its own commits straight to the main branch using a token with no admin standing and no way to satisfy a required review, so the same rule that was meant to stop an unreviewed merge also stopped the hourly price check from running at all.

The agent's own safety rules then stopped it from turning branch protection back off by itself, since undoing a safety control is exactly the kind of change that rule exists to gate. A person had to step in and revert it by hand the same day, rather than risk a gap in collection while the real fix, a separate identity for the hourly check that branch protection can allow through, gets built.

Six commits got blamed on the wrong agent

An audit accused the agent that builds the site of pushing six commits straight to the main branch with no review, reasoning from the fact that those six commits never showed up in the project's own activity log. All six commits carry a timestamp eight hours ahead of the server's clock. That offset belongs to Sebastian's own laptop, not to any agent, which runs on a server set to the same time zone the commits were checked against.

The finding was wrong and was corrected on the record the same day. The activity log it was reasoned from only ever sees one particular tracker, and a log that cannot see a person's laptop proves nothing about what that person did on it. The rule that came out of this: an agent is never blamed for a commit just because a log doesn't mention it. The log has to actually be capable of seeing the thing it's being used to judge.

34 days of checks that quietly found nothing

An early version of the hourly price check was pointed at a hostname that didn't resolve, basically a typo, and was put on an hourly schedule without ever being run once by hand first. It ran every hour for 34 days and recorded nothing but connection errors. From the outside there was no way to tell: no wrong number was published and no row was invented, there was simply nothing, hour after hour, and nothing was watching for "nothing" as its own kind of failure.

The fix was a rule, not a smarter program: nothing goes on a schedule until it has been run once by hand as a dry run that prints exactly what it would have written and writes nothing. Every hourly check has that step now. A 34 day silent failure doesn't need a bug. It needs nobody looking at the first real output before automating the next thousand.

A misplaced key burned $10 in twenty minutes

Two separate credentials run this system. One is a flat subscription for the three agent loops. The other is a narrow, metered key used only by the one feature that calls a model on every public request. They are meant to never live in the same file. For a short while, because of a configuration change, they did, and every agent pass in that window ran on the metered key's per-use billing instead of the flat subscription. It burned through a $10 balance, and a little past it, in about twenty minutes.

The fix was structural rather than a rule to remember. The metered key now sits in its own file, read only by the one feature that needs it, with a comment at the exact point it's used explaining why the two credentials can never merge again. The next person editing that file sees the reason before they can repeat the mistake.

88 percent of daily checks paid to learn there was nothing to do

Before a cheap check existed, every agent loop's turn meant waking a full, billed model session just to read the current state and decide what to do next, which was often nothing. Across roughly 3,900 turns a day, 88% of them were exactly that: a full session whose only output was discovering there was no real work waiting.

The fix was almost embarrassingly simple once someone measured it. A plain, free check against the work queue runs first, with no model involved at all, and only if it finds real work does the loop wake a model up. The lesson that stuck: checking often is cheap, so the instinct to slow a loop down to save money is usually solving the wrong problem. The expensive part was never checking often, it was checking with a model instead of a plain request.

The reviewer that cannot approve its own work

Every agent in this system signs in as the same shared account when it talks to the code host. For a while that meant the reviewer and the builder were, as far as the code host could tell, the same account, and the code host correctly refuses to let an account approve its own submission. So the reviewer could not formally approve anything.

The honest fix was to keep that refusal, not route around it. A real, independent approval is the one signal in this whole system that can't be faked, so it is left as the one thing no agent role is able to produce on its own. The reviewer can check things, comment, and merge routine work on its own say, but anything a person would actually see still needs a person to say yes first, in their own words. That's on purpose and stays that way.

21 hours of price history that can never be recovered

Every hourly check writes a growing list of files. Once, a genuinely new kind of measurement was added to what gets written, but not to the explicit list of files the commit step was told to save. The commit step didn't fail loudly. It committed the files it already knew about, then tried to sync with the remote, and that sync was refused because an untracked file was sitting in the way. The whole pipeline stopped there.

21 hours of real, hourly readings were generated, sat on disk, and were never committed. Because the project's own rule is that a gap in history is never backfilled or estimated, those 21 hours are simply gone, and they show up in the record today as a real gap rather than a smoothed over one. The fix has two layers on purpose. Every file a check might write is now named explicitly in the commit step, so a new one has to be added on purpose. And if something tracked gets changed but left off that list anyway, a fallback stages it too, loudly, with a warning, rather than letting the same failure repeat quietly a second time.

The rule underneath all of it

None of these eight came from an agent doing something clever and wrong. Every one of them was some kind of silence: a failure with no signal, a gap nothing was watching for, or an assumption nobody went back and checked. So the standing rule across the whole system isn't "agents should be smarter." It's narrower and more mechanical than that. Nothing gets published unless it traces to a file that was actually collected. A failed attempt stays visible, it is never hidden. A source that doesn't answer gets recorded as failed, in public, rather than quietly dropped from an average. An agent that can't proceed is expected to say so and stop, not improvise around the gap.

That's the actual claim this project makes, once the pitch language is stripped off. Not that four agents can be trusted to run something real with nobody watching, but that it can be built so it doesn't matter whether they can, because when one of them is eventually wrong, the failure is loud, visible, and traceable back to a real file, every time.

Ops details on purpose left out of this page: the server address, where credentials live, and every key name. Every incident above is checked against this project's own commits, pull requests, and internal notes before publishing, not written from memory. How it works has the collection method, and the raw code and history have everything else.
